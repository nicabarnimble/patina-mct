## DNS blocker

The package refresh returned exit 0 despite these failures:

```text
Err:1 http://deb.debian.org/debian bullseye InRelease
  Temporary failure resolving 'deb.debian.org'
Err:2 http://archive.raspberrypi.org/debian bullseye InRelease
  Temporary failure resolving 'archive.raspberrypi.org'
Err:3 http://deb.debian.org/debian bullseye-updates InRelease
  Temporary failure resolving 'deb.debian.org'
W: Some index files failed to download. They have been ignored, or old ones used instead.
```

Both upgrade simulations and the actual preparation script reported:

```text
0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
```

`getent ahostsv4 deb.debian.org` exited 2. `/etc/resolv.conf` contains:

```text
# Generated by resolvconf
nameserver 10.10.10.22
```

The active static configuration in `/etc/dhcpcd.conf` contains:

```text
interface eth0
static ip_address=10.10.10.22/24
static routers=10.10.10.1
static domain_name_servers=10.10.10.22
```

Thus, the configured resolver is the host itself. No TCP or UDP port 53 listener
was present after k3s removal. The active default route remained `10.10.10.1`
through `eth0`. These observations do not establish whether DNS worked before
k3s removal or whether the router offers DNS service.

Boot configuration, dhcpcd configuration, network interfaces, SSH configuration,
and authorized keys still matched the private backup. No resolver, address,
route, SSH policy, or password was changed. The documented path preserves network
configuration and does not cover this resolver repair. Resuming requires an
approved DNS resolver and a verified package refresh before repeating preparation.
An apt exit status of 0 alone is insufficient evidence.
